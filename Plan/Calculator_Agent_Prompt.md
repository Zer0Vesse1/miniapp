# 角色与核心任务
你是一个顶级的前端架构师与大模型提示词专家。你的唯一任务是：接收本提示词定义的重构需求，将其转化为高质量、模块化、无样式污染的 production-ready 代码。

---

## 1. 开发目标 (Objective)
- **核心任务**：重构现有的“高级计算器（Advanced Calculator）”网页局部嵌入组件（Widget），使其升级为支持**三种模式一键切换**的现代化计算器。
- **三种模式**：
  1. **普通计算器 (Standard)**
  2. **高级计算器 (Advanced)** (保持原样)
  3. **科学计算器 (Scientific)**
- **样式底线与视觉统一**：**三种计算器的整体视觉风格、色彩美学、按键质感、阴影以及边框，必须严格与“科学计算器图片”保持高度一致与协调。** 普通计算器和高级计算器在切换时，只是改变按键的数量、布局（栅格行数/列数）以及特定功能，其外观视觉语言（深色调、按键圆角、质感、色彩分区）需完美适配科学计算器的工业设计。

---

## 2. 视觉设计与布局规范 (UI/UX)
- **容器与响应式**：
  - 外层包裹一个具备独立类名的容器（例如 `.multi-calc-container`），整体宽度自适应（建议最大宽度限制在 `400px` - `600px` 之间以确保紧凑感），保证在宿主页面局部嵌入时不撑破父元素。
  - 所有内部元素使用独一无二的类名前缀（如 `mcalc-`），**严禁**使用全局标签选择器（如 `div`, `button`），杜绝样式污染。
- **色彩与质感（严格对齐科学计算器图示）**：
  - **背景色**：采用深色调（如暗灰 `#1E1F22` 或 `#2D2F34`），整体呈现高科技沉稳感。
  - **按键分区色彩**：
    - *普通数字键与基础算符*：深灰/中灰底色，白色或浅灰文本。
    - *核心操作键（如 `=`, `ENTER`, `EXE` 等）*：醒目的橙色（如 `#FF9F0A`）或明亮色彩，白字。
    - *功能调节键（如 `SHIFT`, `ALPHA`, `MODE` 等）*：特殊色彩标识（如暗绿/深灰底色加特定高亮字）。
  - **按键形态**：微圆角矩形（`border-radius: 4px` 到 `6px`），带有极其细腻的扁平化边框或微弱的下沉阴影，保证极佳的点击反馈（`:active` 状态微移或变暗）。
- **设置菜单与模型切换**：
  - 在计算器右上角或顶部标题栏保留/新增一个“设置”图标按钮。
  - 点击“设置”时，弹出一个精致的下拉菜单或内嵌模态选项栏 `ModelSelect`。
  - 选项栏内包含单选组或下拉项：`普通计算器`、`高级计算器`、`科学计算器`。
  - 切换模式时，计算器主体布局平滑切换（可带微弱的渐隐渐现过渡特效），同时**彻底重置**当前计算器的内部计算状态与缓冲区。
- **单行内元素对齐**：所有操作行、状态栏内部元素一律使用 `Flexbox` 并设置 `align-items: center`，确保垂直方向绝对居中。

## 3. 核心交互逻辑与各模式行为 (Functional Logic)

### 3.1 统一规范
- **输入校验**：连续输入多个操作符（如 `++`, `*/`）时必须进行合法性拦截或自动覆盖。除法分母为 `0` 时，显示屏清零并闪烁提示 `Error`。
- **UI实时渲染**：按键触发、键盘映射输入必须与显示屏内容毫秒级同步，无卡顿。

### 3.2 普通计算器模式 (Standard)
- **布局结构**：采用 $4 \times 5$ 的紧凑型栅格系统。
- **视觉风格**：**严禁使用图1的亮色皮肤**，必须换成与科学计算器完全一致的暗黑深色工业风格，仅保留最基础的运算键。
- **功能键位**：
  - 数字键：`0-9`, `.`
  - 基础算符：`+`, `-`, `*`, `/`, `=`
  - 辅助键：`AC` (清空), `+/-` (正负号切换), `%` (百分比)
- **显示屏**：单行大字号数字显示，右对齐。

### 3.3 高级计算器模式 (Advanced)
- **核心要求**：完全保持您现有的高级计算器 UI 布局、已有色调与既有交互逻辑，但需要将其无缝包裹在新的切换架构中。

### 3.4 科学计算器模式 (Scientific)
- **布局结构**：高密度紧凑栅格系统（如 $6 \times 9$ 左右）。
- **红线规避原则**：**严格禁止添加原图中被红线划掉的菜单/下拉功能行（即顶部的菜单栏功能一律剔除）。直接从物理实体表达式按键行开始布局。**
- **显示屏（双行高精显示）**：
  - *上方行（公式输入行）*：较小字号，左对齐或右对齐，实时显示用户输入的完整数学表达式（如 `sin(30) + ln(e^2)`）。
  - *下方行（实时结果行）*：大字号，右对齐，显示当前表达式的计算结果或最终等于后的结果。
- **核心算法行为与按键映射**：
  - **SHIFT 键二阶状态机**：
    - 具备一个状态指示灯（在屏幕边缘显示一个小小的 `S` 标记）。
    - 当按下 `SHIFT` 键后，激活第二层函数映射（例如：原本点击 `sin` 键，此时变为触发 `sin⁻¹` ；原本是 `ln`，变为 `eˣ`）。触发一次后 `SHIFT` 状态自动解除。
  - **内置高级表达式解析引擎**：
    - **括号嵌套**：完美支持 `(` 和 `)` 的多层嵌套，正确处理优先乘除逻辑。
    - **三角函数**：支持 `sin`, `cos`, `tan` 及其反函数。必须在 UI 上提供一个 `Rad/Deg`（弧度/角度）切换开关，并严格影响三角函数的计算结果。
    - **对数与幂函数**：支持自然对数 `ln`、常用对数 `log`、任意幂次 `x^y`、开平方 `√`。
    - **常数与阶乘**：支持圆周率 `π`、自然底数 `e` 的直接无缝插入计算；支持阶乘 `n!` 算法。

## 4. 交付与结构要求 (Requirements)
- **高度模块化**：
  - 结构（HTML）、表现（CSS/SCSS）、行为（JavaScript/TypeScript）必须严格分离或采用现代组件化框架（如 React/Vue）的单文件组件规范。
  - 每一个计算器模式应当抽离为独立的子视图组件或布局渲染函数，由主状态机驱动切换。
- **工程安全**：
  - 全局变量零污染。
  - 样式选择器高强度加固，杜绝影响到宿主页面的其他元素的布局。
  - 核心数学解析逻辑若使用原生 `eval()` 必须做好极其严格的字符过滤（或优先推荐使用安全的词法解析器逻辑），防止 XSS 注入风险。
